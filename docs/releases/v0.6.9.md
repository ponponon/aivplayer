## Features

AIVPlayer 0.6.9 strengthens media recovery, editing automation and comparison playback.

- Clip Inbox can persist source-file content hashes, search candidate directories and explain whether a repair matched by content hash, file fingerprint, filename or duration. Collection exports carry the content identity forward for repair on another device.
- Editing projects now retain optional source-file content hashes and use them as the safest recovery signal when media paths change, while preserving source IDs, timelines and undo/redo history.
- AIVPlayer adds a synchronized two-video comparison mode for media in the current playlist. Play, pause, seek and playback rate stay aligned, the secondary video is muted, and the mode remains session-only.
- Derived-cache management now reports cache size and file counts in Settings and safely removes only invalid manifests and expired temporary outputs without touching source media or valid caches.
- The editing agent can generate standard read-only MCP configuration and optionally connect to a matching desktop project through the existing confirmation bridge. Direct apply, shell access and arbitrary file access remain unavailable to MCP.

## Performance and Reliability

- Content hashes are computed as streams, candidate directory scans are bounded, and ambiguous repair matches remain blocked instead of being guessed.
- Collection repair and editing-project recovery preserve revision, snapshot and source-identity checks so stale or conflicting data cannot silently overwrite current work.
- Secondary-video startup now waits for native media readiness before applying synchronized state, avoiding a race between React state and the browser video element.

## UI Improvements

- Full-screen playback uses a focused in-stage control layer, while playback, mute, fullscreen and shuffle controls now derive their label, icon and action from the real current state.
- Web, PWA and Flatpak branding assets now use the current AIVPlayer artwork, with platform-sized icons for browser and desktop launchers.
- The optional project-support prompt has a consistent entry point, four-language copy and a local preference so it does not repeatedly interrupt playback.

## Bug Fixes

- Fixed source-file repair paths that could lose content identity or display an unsafe match when a project or collection moved between directories.
- Fixed secondary comparison playback starting out of sync when the target video had not completed native loading.
- Fixed narrow and full-screen playback control states showing the inverse action or stale accessibility text.
- Fixed cache cleanup and Web/PWA icon wiring so derived files and branded launchers are handled consistently across desktop and LAN Web surfaces.

## 中文说明

### 功能

- Clip Inbox 支持持久化源文件内容哈希、扫描候选目录，并明确展示修复采用的是内容哈希、文件指纹、文件名还是时长；集合导出会保留内容身份，便于在其他设备修复。
- 剪辑工程支持可选的源文件内容哈希；媒体路径变化后优先按内容身份恢复，同时保留源 ID、时间线以及撤销 / 重做历史。
- 播放列表中的媒体支持双视频同步对比播放，播放、暂停、跳转和倍速保持同步，副视频默认静音，且对比槽位只在当前会话生效。
- 设置页新增派生缓存大小和文件数量统计，只清理失效清单与过期临时产物，不触碰源媒体和有效缓存。
- 编辑代理支持生成标准的只读 MCP 配置，也可以通过已有确认桥接连接到匹配的桌面工程；MCP 仍不提供直接应用、Shell 或任意文件访问能力。

### 性能与可靠性

- 内容哈希使用流式计算，候选目录扫描有数量上限，存在歧义的修复匹配会保持阻止，不会自动猜测。
- 选段集合修复和剪辑工程恢复保留 revision、快照及源身份校验，避免旧数据或冲突数据静默覆盖当前工作。
- 副视频启动会等待原生媒体就绪后再应用同步状态，避免 React 状态与浏览器 video 元素之间的时序竞争。

### 界面改进

- 全屏播放改为聚焦于视频舞台内的控制层；播放、静音、全屏和随机播放控件均根据真实状态生成图标、文案与动作。
- Web、PWA 和 Flatpak 品牌资源统一使用新版 AIVPlayer 图稿，并补齐浏览器和桌面启动器所需的多尺寸图标。
- 可选的项目支持提示统一入口和四语言文案，并记住本地选择，避免反复打断播放。

### 修复

- 修复工程或集合跨目录移动后源文件修复可能丢失内容身份，或展示不安全匹配的问题。
- 修复目标视频尚未完成原生加载时，双视频对比播放启动不同步的问题。
- 修复窄窗口和全屏播放控制显示反向动作或过期无障碍文案的问题。
- 修复缓存清理与 Web/PWA 图标接线不一致的问题，使派生文件和品牌启动器在桌面端与局域网 Web 中保持一致。
